# Engineering Conventions

This document outlines the core architectural and coding principles for the Clause codebase. These rules are mandatory for all contributions.

## Code Quality & Style
- **Human Senior Engineer Craft**: Write clean, concise, idiomatic JavaScript (ESM). Avoid narrating comments (e.g. "Step 1", "Initialize variable"). Only comment to explain non-obvious business logic, mathematical constraints, or edge-case rationale.
- **No Artifacts or Shortcuts**: No emojis in code, comments, or commit messages. No `TODO` placeholders left behind, no lorem ipsum text, no dead code or unreferenced imports, and zero `console.log` in committed code.
- **Focused Files**: Files must stay focused and rarely exceed 250 lines. Extract reusable hooks, utilities, and child components rather than copy-pasting.
- **Consistent Naming**:
  - `camelCase` for variables, properties, and functions.
  - `PascalCase` for React components.
  - `kebab-case` for file names and route paths.

## User Interface & User Experience
- **Async State Completeness**: Every asynchronous UI action must explicitly handle loading states, success feedback, and error handling.
- **Skeleton & Empty States**: Every collection or list must render a skeleton placeholder while loading and a descriptive empty state with a call-to-action when empty.
- **Real Wires Only**: Every button, link, and form in the UI must be wired to a real route handler or server action that queries or writes to the database. No dummy `alert()` or no-op handlers.

## API & Data Integrity
- **Zod Validation**: All mutation endpoints and server actions must validate incoming payloads using Zod schemas.
- **Standard Error Format**: Errors must return a consistent JSON structure: `{ error: { code, message } }` with appropriate HTTP status codes.
- **Zero Hallucination Ground Truth**: Every legal assertion and quote generated by models must be verifiable against exact character offsets in the database.

## Commit Standards
- **Conventional Commits**: Use conventional commits (`feat`, `fix`, `refactor`, `chore`, `test`, `docs`, `style`).
- **Formatting**: Lowercase, imperative mood, specific (e.g., `feat(upload): reject non-pdf and non-docx files with a clear message`).
- **Atomic Commits**: One logical change per commit.
- **Anonymity**: Never mention AI tools or assistants in code, docs, or commit messages.
